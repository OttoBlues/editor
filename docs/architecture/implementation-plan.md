## 3. K0：契约和零插件内核

**交付：可在无 DOM、无 HTTP、无具体插件环境启动的内核包。**

1. 建 contracts 方法目录、DTO/schema、错误和事件；划清 Kernel API、Plugin SDK（含 View SDK）、Host Ports 的依赖。先覆盖 describe、sessions、plugins、documents.create/transact/get、事件和关闭；视图描述/绑定/选区契约不包含 DOM。
2. 实现 createKernel、统一分派、CallerContext、会话、纯 text/v1 文档、版本和事务、事件游标、幂等记录、最小写入租约。
3. 插件注册表初始为空，显式注册/启用，构建期检查 kernel 依赖闭包不包含具体插件、DOM 或 Node I/O。
4. 用内存 Host Ports 和纯测试插件夹具验证生命周期；夹具必须标记为测试数据，不进入发行组合。
5. 在现有 Demo 外先验证 contracts/kernel，不更改原运行命令含义；新增命令实际配置后再文档化，必要锁文件一并提交。
6. 定义模型无关 EditingContext、tool/v1 描述与结果、ModelProvider.step、ToolCallRecord 和候选 DTO；具体供应商的消息/工具调用格式不进入 contracts。

验收：零插件启动无文件/网络/监听行为；列表为空，能完成内存文档编辑及 undo；对 .md/.txt 打开、磁盘浏览、保存、模拟和模型请求均返回能力缺失；schema/身份/版本/幂等/租约/事件 gap 测试通过。

**第一项可独立提交的实现**：contracts + 最小 kernel，含空注册表、describe、内存文档事务和版本测试。目录设计与接口草图不算该功能已交付。

## 4. K1：首批插件逐个设计和实现

先定每个插件的清单、端口、配置、错误、权限和虚构夹具，再移植现有逻辑。实现顺序按依赖最少优先：

| 次序 | 独立插件 | 可复用的 Demo 依据 | 独立验收 |
| --- | --- | --- | --- |
| 1 | editor.text | local-files.js 的编解码、plugins.js 的段落规则 | 无磁盘/网络，UTF-8/BOM/换行、精确分块；独立声明类型和页面贡献 |
| 2 | editor.markdown | plugins.js 的结构/安全渲染测试 | 无 DOM 解析、精确 sourceRange；独立 tool/v1 的批准范围结构查询与候选，视图此阶段不挂载 |
| 3 | editor.source.local | server.js 文件读写、鉴权外的资源逻辑 | 授权资源端口、版本化保存、链接/路径、权限及未知结果 |
| 4 | editor.model.simulator | assistant.js 固定规则 | 明确模拟、零网络；step 标准事件、工具请求/结果回流及最终候选，不直接改文档 |

内核负责 focus.js 范围和快照规则、assistant.js 中目标选择/提案/差异/位置映射规则；这些不能混进模拟插件，否则换模型或宿主会再次丢失业务一致性。

模拟器演练工具调用也须通过内核 ToolBroker，不直接调用 Markdown handler。工具随文件插件贡献或独立打包；不把 commands.* 自动暴露为模型工具。

每个插件独立 README、manifest、schema、测试、版本和权限声明。类型和视图可在同包，入口与依赖必须分离；页面实现于 K3 交付。插件之间不偷偷自动启用；发行配置显式选择组合。激活失败、重复 ID、依赖冲突、类型/视图匹配歧义、故障、禁用占用和升级回滚都须测试。

本地源在 Windows 验证符号链接、junction、硬链接、大小写、设备路径/ADS、外部修改、权限失败和临时文件清理；当前无法执行的链接用例要在支持的环境补验，skip 不等于通过。首期只有可信自研插件，不宣称完成恶意代码沙箱。

## 5. K2：无 UI 业务闭环

**交付：纯测试客户端仅经 Kernel API 完成打开 → 编辑 → 引用/关注/聚焦 → 上下文预览 → 模型模拟/插件工具往返 → 差异 → 应用/放弃 → 撤销 → 保存。**

将权威文档、快照、上下文、审查策略、撤销历史、发送计划、任务与保存基线全部移入内核。对本地保存、导入导出、真实文件类型绑定作明确区分；内核可返回 host-effect，但不能假装完成浏览器下载。

先证明不安装模型插件也能 context.snapshot；再装配模型模拟器与工具贡献，验证冻结目录、逐目标 execution、标准 step 循环、ToolReport 和暂存候选。同工具用两种测试模型适配夹具（native/emulated）返回一致规范结果，不调用真实服务，也不暗装生产插件。工具阶段不改变缓冲区，最终结果验证后才产生可应用提案。

必测：非连续范围、只读聚焦、范围外原文、同名导入、同资源多个缓冲区、外部冲突、保存中输入、隐式应用后的输入映射、重试去重、取消/迟到、插件停用/崩溃保住已确认草稿。用无 DOM 夹具验证 views/selections 的匹配、身份、生命周期及 writerId，不执行 UI 入口。对并发和失效的判定必须由内核测试证明，不依赖页面事件触发。

保留 Demo 2 MiB 文件、40,000 字符/400 行模拟和 200 块分页约束。若差异算法沿用二维比较表，先维持上限；扩大前独立测耗时和内存，不能将限额修改当作性能已解决。

工具验收：未声明/未批准调用、只读返回变更、全文超出已批片段、跨目标访问、重复 ID 不同参数、候选重叠、缺少/重复终结事件、累计预算超限、权限撤销和插件升级。取消/失败不发布部分 pending；不能把 SDK 范围检查宣称为恶意代码沙箱。

## 6. K3：插件文档页面与现有网页宿主

先在原生 JS 工作台接 client-sdk + HTTP 适配器，删掉网页中的第二套业务状态和直接文件调用；旧 Demo API 可短期做转发兼容，不独立执行旧规则。

工作台保留标签/分栏、全局上下文和审查入口；文件编辑区域由 document-view/v1 接管。实现 view-sdk 和 view-web 运行时，再为 editor.text/editor.markdown 实现文本、源码/阅读页面；插件决定布局和交互，SDK 管理投影、输入队列、租约及事件重连，业务服务留在内核。无需同时重写整个 UI 框架。

第一条页面切片：打开虚构 Markdown → 插件阅读页选两个不连续块 → 核对源文并填说明 → 建聚焦 → 显式关注 → 模拟生成/审查/应用 → 切源码页 → 撤销/保存。类型绑定与文档 ID 不变，插件只通过统一接口操作。

验收涵盖：

- 输入事务确认和未确认状态可见；IME、粘贴、Tab、undo/redo、Ctrl/Cmd+S，隐式应用安全位置映射。真实 Windows IME 需人工验证。
- 两栏标签移动/隐藏保留文档，关视图与关文档不同；同名导入保持独立。
- 同类型多视图、选择歧义、缺运行时、纯视图插件与无界面能力独立启用；关闭视图不删除既有关注/聚焦。
- 页面源映射覆盖 Unicode、重复文本、隐藏语法、表格字段和非连续范围；选取不自动关注，过期选区拒绝，普通人工输入无需关注。
- 同连接多视图单写、切视图/模式的 IME 与队列交接、故障保留已确认正文、插件升级前关闭占用、迟到桥消息拒绝。
- 应用不写盘、逐文件审查、外部冲突不覆盖、保存中输入不误变 clean。
- 刷新重连仍存活的内核会话，事件 gap 重取快照，旧 session/token/lease 拒绝；未提交 UI 队列不被当作已恢复。
- 原四档字号、双语言、浅深主题、键盘/焦点、320/390/800/1440px 视口保持可用。
- 本地 HTTP 保持回环、精确 Host/Origin、会话令牌、限额和 CSP；代理不开放通配 CORS。
- 上下文预览可在无模型插件时使用；发送前展示工具范围及结果回传目的服务，工具运行/失败/未应用候选状态清晰，兼容适配不标为离线模拟。

完成后才独立评估 React/Vite/CodeMirror 的收益和代价，作为展示层迁移，不影响内核契约。

## 7. K4：第二宿主验证可迁移性

构建极简嵌入测试宿主或无框架桌面测试桥，不要求先决定商业桌面壳。一个用进程内/消息传输，一个用 HTTP，均运行同一 client-sdk 契约序列。

验收重点：仅替换适配器和宿主外壳，零业务规则拷贝；相同内核/插件包的事务、聚焦、模拟、差异、撤销、保存结果一致。第二宿主需有兼容 Web 运行时，实际复用同一插件页面，验证主题、尺寸、键盘与输入法；不能仅用无 UI 测试替代页面迁移验收。身份握手、API/SDK 版本不兼容、缺平台端口/视图运行时、断线和关闭流程均有明确结果。

内核包和所选插件一起迁移；仅复制 kernel 而不带实现插件得到的是空能力内核。部署文档列清运行时、平台端口、插件组合与支持限制，不承诺所有环境一份二进制通用。无 Web 运行时的原生宿主需要自建兼容视图或增加容器。嵌入浏览器页面时保留来源/消息权限校验，不能直接放开整个内核接口。

## 8. K5：真实模型与恢复

首个真实模型插件按服务协议单独设计，使用受控网络和凭据注入，Provider 仅获得已确认上下文、工具描述和结果历史。native/emulated/none 明确声明；文本模拟工具调用的编码/解析在模型插件，无需改内核。接入具体模型前依据其官方文档确定支持范围，不能把通用草案当作服务兼容证据。

先用本地假服务测断流/超时/错误工具格式/未知范围/越权/超限/重复事件/取消/错误输出，再在用户选择服务并确认虚构测试内容后做真实验收。真实连接的兼容适配仍算 connected；不声称 fixed-rule 模拟已验证真实语义或服务工具调用。

持久恢复另设显式开关、schema 版本、保留/清理、资源冲突处理和凭据策略。恢复后重新核对磁盘与插件绑定；不能把旧授权票据、租约或 active run 原样复活。

更多文件类型、插件市场、第三方代码沙箱、大文件和多人协作均为独立需求，不隐含在本期。Linux/macOS 在实际平台/CI 验证后再声称支持。

## 9. 回退与完成门槛

每阶段单独提交可运行切片，保存旧入口或可回退 commit；不以回退方式覆盖用户文件。状态归属切换期间不得让新旧路径同时编辑同一缓冲区，按会话选择一种路径；迁移适配器只转换调用。

内核和插件设计的交付门槛是接口、权限、数据、版本和生命周期都有可执行测试，空内核和完整发行组合分开验收；网站可用不能替代内核可移植性验收。

公开提交前按项目约定核对差异、作者隐私邮箱、样例和日志，仅提交源码/必要配置/锁文件/脱敏文档。计划、跳过项、已执行结果分别记录，不把设计写成实现。
