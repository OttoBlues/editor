## 3. M1：先提取领域规则和契约

**目标：Demo 继续运行，关键规则可脱离 DOM 和 HTTP 单独验证。**

1. 建立最小 TypeScript/workspaces 配置，保留 npm start 和 npm test 的语义；新增命令实际配置后才写 README，锁文件与必要配置一并提交。
2. 从 focus.js 提取范围/快照规则，从 assistant.js 拆出目标选择、提案应用和模拟转换，保留原 export 的薄兼容层。预览 DOM 留在浏览器。
3. 定义文档来源、缓冲区、快照及错误码，提供旧 tab 数据适配，逐步将关注和聚焦改绑 documentId。
4. 增加计划和提案的运行时 schema、虚构夹具及版本测试；前后端共用规则，不共用隐式可变状态。
5. 保持模拟和默认应用策略，通过同名来源、跨分栏回归后继续迁移 UI。

验收：原测试通过或有明确记录的行为变更；领域测试不依赖浏览器、磁盘或网络；关注、精确范围、合并和逐文档应用一致；依赖不跨层，类型检查与构建真实通过。

回退：入口切回兼容导出，不改变磁盘文件格式或运行数据布局。

**建议下一项工作**：只提取纯领域规则并接回现有 Demo，完成带回归证据的提交，不同时扩大文件权限或接真实模型。

## 4. M2：工作台与编辑器迁移

**目标：拆解 app.js 的共享状态与 DOM 编排，保留已有体验。**

先完成单文档纵向切片：React 工作台 → DocumentStore → CodeMirror EditorAdapter → 现有保存适配器；再扩展标签、双栏、聚焦、预览和审查。保持四档字号、主题、语言、窄屏和键盘入口。

EditorAdapter 至少提供读取选区、编辑事务、替换正文、订阅变更、设置只读、释放视图；CodeMirror 对象不进入领域记录。独立文档各有内容及撤销状态，视图只是订阅者，不能每次输入重建编辑器而重置输入法和选区。

| 场景 | 验收要求 |
| --- | --- |
| 标签/分栏 | 草稿、焦点、滚动独立；移动保持 documentId；收起不丢内容 |
| 同磁盘文件多栏 | 缓冲区独立，保存冲突可见，不误合并关注与提案 |
| 同名外部文件 | 独立副本，仅导出，不绑定演示目录文件 |
| 上下文 | 引用快照、关注目标、聚焦范围互不替代，关闭来源规则不变 |
| 审查 | 完整左右对比、逐文件应用/放弃、过期不覆盖、应用不保存 |
| 输入 | 中文 IME、粘贴、Tab、撤销/重做、位置映射、Ctrl/Cmd+S |
| 易用性 | 键盘、可见焦点、双语言、浅深主题、320/390/800/1440px 视口 |

浏览器自动化建议采用 Playwright；Windows 中文输入法仍须人工验证，脚本 composition 事件不能完全替代系统 IME。截图仅用虚构样例并记录实际环境。

回退：迁移期间保留旧页面入口或明确回退 commit，不长期维护两套界面。

## 5. M3：本地内核与授权工作区

**目标：从固定演示目录演进到用户明确授权的普通本地目录。**

将 server.js 拆成认证/路由、工作区/文件服务及文件系统适配器；M1/M2 保持旧接口，M3 增加 v1 后逐步切客户端，移除旧接口时同步测试与文档。

首个授权入口采用本地启动参数或配置指定根目录，具体语法实施后记录。浏览器只列已授权根，无注册任意绝对路径接口；原生目录选择和桌面壳不是前置依赖。

实现 fileId、目录分页、路径与链接限制、格式保持、文件写入队列和版本冲突检查，补齐保存响应丢失及保存中继续输入的行为。文件监视可后加，不能代替保存重读。

验收门槛：

- Windows 覆盖大小写、junction、符号链接、硬链接/别名、设备路径、ADS、越界；不支持的路径明确拒绝。
- 外部编辑、删除/替换、只读、权限失败、临时文件清理、写失败及并发保存，失败均保留缓冲区。
- Host/Origin/token 和 CSP 保留；开发代理通过同类测试，不能开放任意来源。
- 在允许建链接的环境运行此前跳过的测试，skip 不能视为安全门槛完成。
- 增加 Linux/macOS CI 或复现记录后，才声称这些平台已验证。

回退：仍可运行演示目录模式，不自动覆盖真实工作区或删除用户文件。

## 6. M4：真实模型闭环

**目标：选择内容 → 确认发送 → 模型任务 → 校验提案 → 审查应用 → 手动保存。**

先完成 PreparedPlan、任务状态与离线 Provider，再接一个明确的真实协议。模拟与真实模式在界面中清晰区分。服务商尚未指定，属于接入阶段待确定项，不阻塞领域与 UI 拆分。

实施内容包括模型配置版本、会话凭据与可用时的安全存储、发送清单、目标输入隔离、流式进度、取消/重连、幂等任务、候选校验、配额和脱敏诊断。

用本地假服务验证超时、断流、错误 JSON、未知范围、跨文档输出、重复事件、迟到响应、预算耗尽和部分子请求失败。核对未选文件、未选正文、绝对路径和凭据不会进入发送正文；测试密钥只进入服务认证入口。

真实服务验收在用户指定服务、提供自己的凭据并确认发送虚构测试内容后执行。模拟/假服务通过不等于真实接入已验证，真实密钥不进入测试或提交。每个 Provider 记录能力、限制和实际验证范围。

回退：禁用真实 Provider，继续离线模拟；清除凭据不删除用户文档。

## 7. M5：恢复、性能与扩展

以下是可选后续工作，没有本轮排期承诺：

- 草稿恢复：定义本地持久化开关、位置、留存/清理、崩溃恢复与隐私，恢复后重新比较磁盘。
- 大文件：先测编辑、分块、差异的时间与内存，再选择 Worker、增量处理、虚拟化或有界差异算法，逐项提高限额。
- 新文件类型：先做内置适配器；复杂格式需要独立编辑协议，不能全部当字符串替换。
- 桌面封装：原生文件选择、安全存储、分发成为明确需求后评估，保持网页与内核边界。

第三方扩展、共享缓冲区多视图、跨设备同步、多人协作均需新决策，不隐含在此设计内。

## 8. 关键取舍与重新评估条件

| 决策 | 理由 | 改变条件 |
| --- | --- | --- |
| 一个本地模块化内核 | 当前单用户、文件/模型 I/O 为主，复用 Node | 不可信插件或明确进程隔离需求 |
| React + TypeScript + Vite | 状态和生命周期复杂，构建后仍由本地内核提供页面 | 切片无法维持输入、焦点、加载成本或维护收益 |
| CodeMirror 经端口接入 | 统一事务、选区、撤销，允许替换 | IDE/语言服务成为核心，或真实输入验收不达标 |
| HTTP + 单向事件流 | 文件操作和模型进度足够 | 真正需要持续双向同步 |
| 首期无数据库 | 偏好少，正文会话内，无历史查询 | 恢复、索引、历史检索需求明确 |
| 内置处理器 | 当前两种文本，无第三方权限/隔离协议 | 明确插件需求且隔离设计完成 |
| 独立文档缓冲区 | 保持现有多栏和冲突语义 | 用户选择共享内容与撤销历史的多视图 |

后续需确认：首个真实协议、是否开放 explicit-only 审查选项、草稿恢复默认值、真实目录授权的最终界面及下一文件类型。已有可行默认值，不为这些问题阻塞 M1。
